# 定级、评分与中文写作规范

## 严重度
- **major**：若成立，会改变对论文主要声明是否成立、或是否达到目标会议标准的判断。例如：关键结论缺少支撑、比较不公平且影响排名、方法有错误、核心“首次”声明不成立。
- **minor**：不影响主要结论，但影响清晰度、完整性或次要声明。

## 置信度（意见级）
- `high`：有直接原文证据，并且反证检查已排除主要辩护。
- `medium`：证据较强，但存在合理的另一种解释或少量信息缺失。
- `low`：依赖推断或未能完全核实，通常应写成 `question`。

## 总评置信度（1–5，与多数会议一致）
5 非常确定，熟悉领域且核对了细节；4 有把握；3 较有把握；2 可能遗漏核心部分；1 有根据的猜测。没有复现实验、未读部分附录时，一般不超过 4。

## 从意见到总评
1. 列出 `decisive_ids`：真正决定推荐的 1–3 条意见（可以是优点）。
2. 按下文“评分底线条例”出分：先判核心贡献，由判定确定分数范围（G7）与起评分（G6），最后做反向校验（G13）。
3. 写 `would_change`：作者做到哪些事会让你提高或降低分数。
4. 不用问题数量决定分数（G8）；不因为论文出自知名团队或已被录用而调整分数（盲审时不应知道）。

## 评分底线条例（v1.5.1）

**目的**：让审稿把篇幅和分量放在决定论文价值的问题上——核心主张是否有证据支撑、证据链在哪里断开。写作与呈现问题照常指出，但不与核心问题并列，也不替代对核心问题的判断。条例不预设分数高低：它既不是为了放宽，也不是为了收紧，而是为了让判断落在论文真正薄弱的地方。

各会议、各年份的评分细则并不一致，本技能统一使用 1–6 分量表：1 Strong Reject、2 Reject、3 Weak Reject、4 Weak Accept、5 Accept、6 Strong Accept。4 分及以上为倾向接收，3 分及以下为倾向拒绝。条例中的“核心贡献判定”是出分的主要依据；问题三级制（G1）是辅助，用来把问题的严重程度与它是否查实分开判断。

> G1 的分级与 G7 的分数范围仍在验证中，可能调整。

### 核心贡献判定（第 2 步写出，第 9 步定稿）
1. **找出核心主张（最多 3 条）。** 判别：去掉这条主张，论文是否仍值得发表？仍值得则为次要主张。
2. **确定所需证据。** 方法更好：条件对等下胜过最相关的强基线；基准/数据集：真值可靠、规模与覆盖属实、确实测到所声称的能力；理论：主定理证明链完整；实证发现：在多个设置下重复出现；系统/工具：功能实现且可用。
3. **找出证据链**：哪些表、图、定理支撑该主张。
4. **逐条检验 A/B 类问题的影响**：
   - **切断**：论文**现有**证据已不再支撑该主张。例如主结果与自身数据矛盾；在公平条件下增益消失；混杂因素能完全解释增益；主定理证明链断开。
   - **收窄**：现有证据仍支撑该主张，但范围、幅度变小，或其中一部分尚未验证。例如缺最相关的强基线或关键消融（主张改写为“优于文中比较的基线”）、只在部分设置下成立、增益幅度小于所声称的。离线审稿无法知道缺失的基线是否更强，按收窄处理。
   - **无关**：不影响该主张。
5. **改写为证据能支持的最强版本。** 例如“所有数据集 SOTA”被自己的表格反驳，改写为“三个数据集中两个领先、一个与最强基线相当”。
6. **判定**：成立（改写后仍是有意义的贡献，且仍是论文自己声称的贡献）/ 部分成立（改写后明显缩水，失去部分主要卖点，但仍有剩余）/ 不成立（证据链被切断）。

| 问题 | 对核心主张的影响 | 通常导致的判定 |
|---|---|---|
| A 针对核心主张 | 切断 | 不成立 |
| B，现有证据已不支撑主张 | 切断 | 不成立或部分成立 |
| B，现有证据仍支撑，但范围变窄或部分未验证（如缺基线、缺消融） | 收窄 | 成立或部分成立（看改写后缩了多少） |
| C | 无关（只影响改写措辞） | 成立 |

**说过头不等于不成立**：主张说过头只导致第 5 步的改写，问题按 C 或 B 处理；只有证据链被切断才判“不成立”；反之，证据链被切断时不能用改写把主张缩到无关紧要来保住“成立”。C 类问题不能切断证据链；A 类问题针对核心主张时只能是切断。判定写入 `overall.core_claims`（见 schema.md）。

**分数只由判定决定。** 问题级别（G1）用来推出判定，不再单独限制分数；G6 的起评分、G7 的范围与 G13 的反向校验都以同一组判定为依据。

### 条例
- **G1 问题三级（辅助）。** 每条非优点意见标 `tier`：A 致命（推翻核心结论：主定理错误且无法修复、测试集泄漏直接造成主结果、主结果与自身数据矛盾、伦理或诚信问题）；B 实质（削弱核心结论，但可通过补实验或补分析回应：缺关键基线或消融、增益来源混杂、指标测不到声称的能力、适用范围过窄）；C 可修改（措辞夸大、不影响结论的数字或表格笔误、次要定理的常数或符号错误、细节缺失）。B 对核心主张是切断还是收窄，按“核心贡献判定”第 4 步区分。
- **G2 查实不等于严重。** `status: confirmed` 与 `confidence: high` 说明问题真实，不说明它严重；查实的笔误仍是 C；推翻核心结论的问题无论表现为一个数字还是一处推导，都是 A。
- **G3 数字不一致。** 落在核心卖点且偏向作者有利方向 → B；改正后核心结论不成立 → A；其他 → C。
- **G4 理论错误。** 支撑核心主张的主定理错误 → A；可局部修复或修复后结论仍成立 → B；次要引理、常数、推导细节 → C。
- **G5 测试集选参。** 默认 B（通常为收窄）；按选择带来的噪声估算，报告的增益已落在噪声范围内时，该结论为 A（切断）。
- **G6 先判贡献（主依据）。** 按上文“核心贡献判定”给出每条核心主张的判定与贡献重要性（`significance`: high / medium / low）。起评分取 G7 对应范围的默认值，再按重要性在范围内调整：high 可取上限，low 取下限；`significance` 为 low 时可再比下限低 1 分，并在 `blocking_issue` 写明理由。
- **G7 分数范围（由判定决定）。**

  | 核心主张判定 | 分数范围 | 默认 |
  |---|---|---|
  | 有不成立 | 1–2 | 2 |
  | 有部分成立（无不成立） | 2–3 | 3 |
  | 都成立，仍有针对核心的收窄型 B 未解决 | 3–4 | 4 |
  | 都成立，针对核心的只有 C（B 只涉及次要主张也算此档） | 4–5 | 4（5 须 `significance: high`） |
  | 都成立，贡献重要（high），无问题或零星 C | 5–6 | 5 |

  另外两条与判定无关的限制：伦理或诚信类 A 问题，不论针对哪条主张，分数 ≤2；A 只涉及次要主张时，该主张须删除或改写，分数不超过 4。
- **G8 不按数量累加。** C 不叠成 B，B 不叠成 A；只有共同指向同一核心结论时才合并升级，并写明理由。
- **G9 3 分须写明阻断问题。** 给 3 分时在 `overall.blocking_issue` 写明不解决就不能接收的问题：部分成立时，写造成主张缩水的那条问题；核心主张都成立时，写哪条收窄型 B 必须补上，或写“贡献重要性不足”并说明理由。写不出则给 4。
- **G10 基准与数据集论文。** 资源本身的价值计入贡献；指标效度问题为 B，不为 A（除非真值本身无效）。
- **G11 理论论文。** 主结论的证明链必须完整；附录次要部分的错误按 G4 处理。
- **G12 创新性证据不足。** 离线审稿或未读前作原文时，创新性意见只能为 B 或 C，不能作为拒绝的主要理由。
- **G13 反向校验。** 出分前分别写出“若被接收，最可能的原因”与“若被拒，最可能的原因”，写入 `overall.g13_check`。前者是“核心主张都成立、没有切断型问题”且 `significance` 不低于 medium 时，分数不应 ≤3；后者指向一条切断型问题（A，或切断证据链的 B）时，分数不应 ≥4。校验与分数冲突时，回到核心贡献判定重查影响与判定，不直接改分。

### 各步骤中的位置
| 步骤 | 条例 |
|---|---|
| 第 2 步 理解论文 | 核心贡献判定第 1–3 步；G10、G11 确定论文类型的标准 |
| 第 3 步 创新性 | G12 |
| 第 5 步 定级 | G1–G5：写意见时就标 `tier`，与置信度分开 |
| 第 8 步 复核 | 复核者检查 tier 是否偏重或偏轻、切断/收窄是否判对、改写后的主张是否超出证据 |
| 第 9 步 总评 | 核心贡献判定第 4–6 步（切断/收窄）；由判定定范围与起评分（G6、G7），G8、G9、G13 |
| 第 11 步 英文提交稿 | Weaknesses 按对核心主张的影响排序（切断 → 收窄 → 其他）；C 类合并为一条“写作与呈现”；Justification 指出最弱的一环 |

## 一条好意见的结构
> **[标题：一句话说清问题]**
> 现象：在第 X 页 / 表 Y 中，作者声称……（引文）
> 为什么重要：该声明支撑了贡献 C2；若不成立，……
> 已排除的解释：检查了附录 B 与 §4.3，作者……，但……
> 请求：请补充 ……（具体到数据集、设置、指标）
> 影响：若补充结果支持该声明，此条不影响评价。

## 反例（不要这样写）
| 不好的写法 | 问题 | 改写 |
| --- | --- | --- |
| “创新性有限。” | 没有比较对象 | “C1 的交替注意力与 Fast3R v1（2025-01-23）§3.1 的……在……上相同，差异在……，建议修正‘首次’表述。” |
| “实验不充分，应在更多数据集上验证。” | 不说明缺什么 | “可扩展性声明（p.1）缺少 N>24 视图的精度结果，建议报告 N=50/100/200 下的相机误差。” |
| “写作需要改进。” | 无法操作 | “§3.2 中 \(T_i\) 与 \(t_i\) 混用（p.4 公式 3、5），建议统一。” |
| “没有和 XX（2025 年 6 月）比较。” | 晚于截止日期 | 删除，或在“同期工作”中提示讨论 |
| “结果不稳定。” | 未报告方差 ≠ 不稳定 | “未报告多种子方差，建议补充 3 个种子的标准差。”（`suggestion`） |

## 中文写作规范
- 正文简体中文，语气专业、平和、对事不对人；不用“作者显然没有理解”这类措辞。
- 术语首次出现写“中文（English）”，之后可用中文；方法名、数据集名、指标名保留原文。
- 引文保留原文，不翻译；在引文后用中文解释。
- 数字带单位，百分比与百分点区分清楚（“提高 6.4 个百分点”≠“提高 6.4%”）。
- 每条意见只讲一件事；合并重复意见。
- 较长的意见按“现象 → 证据 → 影响 → 请求”用空行分段；并列的几点写成 (1)(2)(3)。
- 公式写成 LaTeX：行内 `$...$`、独立 `$$...$$`（如 `$\min(Q_{\bar\theta}, Q_\theta) \le Q_{\bar\theta}$`），不用 Unicode 符号拼写公式；阅读器与英文提交稿都会渲染。单纯的数字对比（如 0.52→0.73）照常写成文字。
- 自查模式（面向作者）：用“建议”“可以”代替“必须”，并给出改法；同时标出审稿人最可能抓住的点。
