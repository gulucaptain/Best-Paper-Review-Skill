# 候选批评的反证检查

每条重要批评先作为候选，不直接写入。逐项检查：

1. **搜全文**：正文、附录、补充材料、图注、表注、脚注。用快照全文搜索关键词与同义词。
2. **核对定义与设置**：单位、尺度、数据划分、评测协议、是否使用真值输入。
3. **最强辩护**：以作者的立场写一句最有力的回应。
4. **判定**：证据能否消解辩护？
   - 能 → 撤销或改为 `suggestion`；
   - 部分能 → `limitation` 或 `question`；
   - 不能且有直接原文证据 → `confirmed`。
5. **范围**：结论只说证据支持的范围。“缺少 X 的定量证据”不等于“方法在 X 下失败”。

## 必须降级的情况
图表不清晰无法读数；来源无法访问；截止日期或版本不明；只读到摘要；依赖未核实的复算；论文类型不同导致期望不同。

## 常见的“看起来像问题”的情况
| 表面现象 | 先检查 |
| --- | --- |
| 没有多随机种子 | 附录是否报告方差；是否是确定性评测 |
| 提升很小 | 是否同时降低了成本，或该指标是否接近饱和 |
| 与 X 方法名字相似 | 机制、假设、输入是否真的相同 |
| 没和最新方法比较 | 该方法是否晚于截止日期，是否可复现 |
| 参数更多所以不公平 | 是否有等参数量消融 |
| 数据更多 | 是否有同数据量对照；声明是否本来就包含数据规模 |
| “未定义符号” | 是否在附录或前文定义 |
| 速度声明夸大 | 计时口径（仅骨干/端到端、批大小、硬件）是否注明 |
| 局限性 | 作者是否已在 Limitations 中披露 |
| 理论不严谨 | 论文是否声称理论贡献 |

## 量的要求
- 不规定缺点数量。没有 major 问题的论文可以没有 major 意见。
- 不要为了平衡而硬写优点；优点同样需要证据（表格数字、消融结论）。
- 每条 `confirmed` 意见至少有一条稿件原文引文，并写清反证检查。

## 质量评估（迭代本技能时使用）
评测集应同时包含真实缺陷与上表中的“伪问题”，统计：重要问题召回率、错误发现比例、证据蕴含准确率。人工评审意见和录用结果都不是自动的标准答案。`tests/eval_synthetic.py` 提供一个合成论文的最小评测。
